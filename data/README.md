# Reference route data

## `reference_route.csv`

A synthetic reference route (~1.0 km, 1871 points) laid out the way real road
geometry is: straights joined to constant-radius arcs by linear-curvature
(clothoid) transitions. Four bends (R = 200, 30, 150 and 25 m) give the
controllers a mix of gentle sweeps, two tight junction-style turns, and long
straights to settle on.

The file is generated by
[`tools/generate_reference_route.py`](../tools/generate_reference_route.py) from
the curvature profile declared at the top of that script — edit `PROFILE` and
re-run it to produce a different route:

```bash
python tools/generate_reference_route.py [output_csv]   # default: data/reference_route.csv
```

No third-party map or survey data is used, so this CSV carries no licensing
obligations beyond the repository's own Apache-2.0 terms.

### Columns

```
x_m, y_m, yaw, curvature
```

| Column | Unit | Meaning |
|--------|------|---------|
| `x_m`, `y_m` | metres | Planar position, origin at the first route point, `x_m` East / `y_m` North. |
| `yaw` | radians | Path tangent heading, wrapped to (−π, π]. |
| `curvature` | 1/m | Signed path curvature (left turn positive). |

### What the simulation uses

The path-tracking code reads all four columns, locating them by header name
(see `include/path_tracking/path_io.hpp`), so extra columns and a different
column order are accepted. Arc length and a curvature-limited reference speed
profile are derived automatically at load time.

### Using your own route

Any CSV carrying `x_m`, `y_m`, `yaw` and `curvature` header cells works. The
first data point defines the local origin, and `x_m`/`y_m` should be in metres.
